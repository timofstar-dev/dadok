# 다독다독 세계여행

HTML/CSS/JavaScript 독서 기록 앱입니다. Cloudflare Pages에서 제공하며, 책 검색은 Pages Functions를 사용합니다. 화면만 확인할 때는 별도 빌드 없이 실행할 수 있습니다(이 서버에서는 책 검색 API를 제공하지 않습니다).

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

대시보드는 전교생·반별 탐험가를 표시합니다. 기존 대륙 도착 기준(0, 700, 900, 1600, 1800, 2300, 3000걸음)을 유지하며, 대륙 사이의 진행 위치를 계산합니다. 이름표는 충돌하지 않는 가까운 자리에 표시하고, 탐험가를 누르면 경로상의 정확한 위치와 남은 걸음, 도착 도장을 확인할 수 있습니다. 학생 수가 많으면 지도가 세로로 늘어납니다. 100%에서는 화면에 전체 지도를 맞춥니다. 작은 점은 실제 경로 위치이며, 이름표에 마우스를 올리거나 키보드로 포커스하면 연결선을 보여줍니다. 휴대전화에서는 **이름으로 위치 찾기**로 학생을 선택하고 **이름 크게 보기**로 확대해 확인할 수 있습니다.

- `journey-model.js`: 이동 거리와 겹치지 않는 이름표 배치 계산
- `journey.js`: 반별 조회, 탐험가 선택, 도장, 도착 효과
- `journey.css`, `images/travel-world.svg`: 대시보드와 그림 지도
- `index.html`: 기존 기록·리더보드·대시보드 통합

앱 데이터는 `index.html`의 Google Apps Script API에서 읽습니다. API 서버 코드는 이 저장소에 포함되어 있지 않습니다. 도착 효과는 이 페이지가 이미 읽었던 기록보다 새로 조회한 걸음이 늘어 대륙 기준을 넘었을 때 표시합니다. 자동 폴링이나 서버 점수 계산 방식은 변경하지 않았습니다.

## 검증

```sh
node --test tests/journey-model.test.js
python3 tests/journey-browser.py
```

브라우저 검증에는 Python Playwright와 `/usr/bin/chromium`이 필요합니다. 테스트는 임시 로컬 서버와 가상 학생 데이터로 실행되며 실제 API로 기록을 전송하지 않습니다. 기존 Bulma CSS만 TLS 검증을 유지한 채 내려받아 `/tmp/dadok-bulma.css`에 캐시합니다. 화면 캡처는 `/tmp/dadok-world-map.png`, `/tmp/dadok-expedition-desktop.png`, `/tmp/dadok-expedition-mobile.png`에 생성합니다.

## 책 검색 도우미

`기록하기` 탭 위의 **책 검색 도우미**를 열면 제목 검색 → 판본 선택 → 저자·전체 쪽수 확인 → 적용 순서로 사용할 수 있습니다. **제목·지은이만 적용**은 기존 읽은 페이지 수를 보존합니다. **다 읽었어요**는 제목과 전체 쪽수를 함께 입력합니다. 검색이나 판본 선택만으로 입력값을 바꾸거나 독서 기록을 저장하지 않습니다.

- `book-catalog.js`: 같은 앱의 `/api/books/search`, `/api/books/details` 호출과 판본 검증.
- `functions/api/books/`, `functions/_lib/yes24.js`: YES24 검색 페이지와 선택한 상품의 상세 정보를 서버에서 읽습니다. 제목·저자·출판사·출간일·ISBN·전체 쪽수를 반환합니다. 학생 정보는 보내지 않고 검색 제목과 상품 번호만 전송합니다.
- `book-helper.js`, `book-helper.css`: 독립 검색 메뉴, 판본 목록, 정보 확인·적용. 저자 또는 쪽수가 없으면 추측하지 않으며, 쪽수 적용 버튼을 비활성화합니다.
- 자동 정보 조회는 YES24를 사용합니다. **YES24에서 검색**, **교보문고에서 검색**은 현재 제목을 해당 서점의 새 창으로 전달합니다. 교보문고 정보를 자동으로 입력하는 기능은 아닙니다.
- 별도 API 키나 Apps Script 변경은 필요 없습니다. Cloudflare Pages 배포 시 `functions/`와 `_routes.json`을 포함해야 합니다. `_routes.json`은 `/api/books/*`만 함수로 처리합니다. 일반 정적 호스팅에서는 자동 검색이 동작하지 않습니다.
- YES24 공개 HTML을 읽는 방식이므로 서점의 페이지 구조 변경이나 접속 제한 시 조회가 실패할 수 있습니다. 오류 응답은 캐시하지 않으며 검색 결과는 10분, 상세 정보는 6시간 서버 캐시합니다. 실패할 때에도 서점 직접 검색과 기존 수동 입력은 사용할 수 있습니다.

Functions를 포함한 로컬 실행(최초 실행 시 Wrangler 설치):

```sh
npx wrangler@4.153.0 pages dev . --compatibility-date=2026-07-01
```

서버 테스트는 Cloudflare의 실제 HTMLRewriter 런타임(Miniflare)을 사용합니다. 개발 의존성 설치 후 실행합니다.

```sh
npm ci
npm test
python3 tests/book-helper-browser.py
```

브라우저 테스트는 가상 도서와 학생 데이터로 판본 선택, 기존 입력값 보존, 쪽수 누락, 검색 실패, 응답 순서 역전, 서점 바로가기, 키보드·모바일 화면을 검증합니다. 실제 API로 독서 기록을 전송하지 않습니다. 예시 화면은 `/tmp/dadok-book-helper.png`에 생성됩니다. 외부 서비스 가용성은 이 회귀 테스트와 별도로 배포 후 실제 검색으로 확인해야 합니다.

2026-10-27 YES24 실제 검색·상세 HTML에서 『푸른 사자 와니니』(상품 번호 18841857, 이현, 창비, 216쪽, ISBN 9788936442804)를 확인했습니다. `tests/fixtures/yes24/`는 이때 받은 공개 페이지에서 파싱에 필요한 부분을 발췌한 회귀 테스트 자료입니다.

## 학년도와 자동 진급

조회 학년도는 서울 시간 **3월 1일~다음 해 2월 말**입니다. 지도·순위·월별 통계·개인 기록·복사 목록은 선택한 학년도의 기록만 사용합니다. 1·2월은 직전 학년도에 속합니다. 현재 학년도와 공식 명부가 있는 학년도는 해당 명부만 인원수·지도·순위·월별 통계의 기준으로 사용합니다. 명부에서 제외된 학생은 과거 기록이 남아 있어도 다시 추가하지 않습니다. 공식 명부가 없는 이전 학년도만 저장된 기록으로 당시 명부를 복원합니다. 원본 독서 기록은 삭제하지 않습니다.

`school-config.json`의 `rosterYear: 2026`은 현재 Google Apps Script 명부의 기준 학년도입니다. 매년 3월 1일 기준으로 학년을 계산하고, 12학년을 초과하면 현재 입력 명부에서 제외합니다. 과거에 저장된 학년·반·기록은 수정하지 않습니다. 페이지가 열린 상태에서도 날짜 변경을 확인합니다. **원본 명부를 새 학년으로 직접 갱신한다면 `rosterYear`도 함께 갱신해야 중복 진급을 피할 수 있습니다.** 원본 API가 `{rosterYear:2027, students:{...}}` 형태로 기준 연도를 반환하면 그 값을 우선합니다.

반 이름은 코드에 고정하지 않고 명부에서 읽습니다. 반 이름만 바뀔 때는 `classNamesByYear`에 변경할 학년도를 지정할 수 있습니다. 예시(실제 반 이름 변경 지시가 아니므로 현재 설정에는 넣지 않았습니다):

```json
{"classNamesByYear":{"2027":{"예전반":"새반"}}}
```

다음 연도에도 새 반 이름을 유지합니다. 신입생·전학생·반 편성이 바뀌면 `rostersByYear`에 **해당 학년도 전체 명부**를 제공할 수 있습니다. 구조는 `{ "2027": { "1": { "반이름": ["학생이름"] } } }`입니다. 명시한 연도의 명부가 자동 진급보다 우선하며, 이후에는 가장 최근 명부를 기준으로 진급합니다. 학생 명부는 기존 Apps Script에서 관리하고 `rostersByYear`로 반환하는 방식을 권장합니다.

필독서도 학년도별로 구분합니다. 기존 API의 `allRequiredBooks`는 명부 기준 학년도에만 적용합니다. API에서 `allRequiredBooksByYear: {"2026": {"11월": {"반이름": "책제목"}}}`를 반환하면 각 학년도의 설정을 사용합니다. 설정이 없는 학년도에 다른 해의 필독서를 가져오지 않습니다.

## 저장 결과와 검증

HTTP 오류·오류 JSON·확인할 수 없는 응답은 기록완료로 표시하지 않으며 입력을 유지합니다. 기존 Apps Script의 유효한 `{steps: 숫자}` 응답과 `success/status`를 포함한 성공 응답을 지원합니다. 서버 응답이 오기 전에 중복 제출을 막습니다. 전송 후 응답을 받지 못하면 저장됐을 가능성도 있으므로 기록을 확인하도록 안내합니다. 저장 성공 이후 목록 갱신이 실패한 경우에는 저장 실패와 구분해 재저장을 막는 안내를 표시합니다. 실제 Apps Script 소스가 저장소에 없어 서버 자체의 검증·중복 방지 방식은 변경하지 않았습니다.

`npm test`는 기존 도서 검색과 지도 테스트에 더해, 서울 시간 진급 경계·졸업·반 이름 변경·학년도 분리·오류 응답·입력 보존·중복 제출·저장 후 조회 실패를 가상 데이터로 검증합니다. 운영 API로 테스트 기록을 저장하지 않습니다.

## 독서 퀴즈 인증

퀴즈가 있는 책은 **퀴즈를 통과해야** 기록되고, 퀴즈가 없는 책은 지금처럼 **독서록으로 기록**하면서 선생님께 출제를 요청합니다. 정답과 채점은 Apps Script 서버에서만 처리하며 학생 화면에는 보내지 않습니다. 서버 코드는 별도 Apps Script 프로젝트(clasp로 관리)에 있습니다.

### 걸음 계산

```
걸음 = 쪽수 걸음(10 + 쪽수÷10, 10~40) + 학년 보너스(7~8학년 +5, 9~12학년 +10)
     − 퀴즈 감점(100점 0, 10점 모자랄 때마다 2걸음) + 독서록 보너스(0/2/3/5/7/10)
```

- 60점 이상이면 통과합니다. 통과하지 못하면 아무것도 저장되지 않고, 그 책은 **서울 날짜 기준 7일 뒤**부터 다시 풀 수 있습니다.
- 퀴즈로 이미 인증한 책은 같은 학생이 다시 인증할 수 없습니다.
- 퀴즈 기록은 `전체기록` 시트의 I열(퀴즈 점수)과 J열(인증 방식: 퀴즈/독서록)에 함께 남습니다. 기존 화면은 A~H열만 읽으므로 영향이 없습니다.

### 선생님이 관리하는 시트

시트는 서버가 처음 필요할 때 자동으로 만듭니다.

| 시트 | 열 | 설명 |
|---|---|---|
| `퀴즈도서` | 도서ID · 책 제목 · 지은이 · 단계 · 상태 · 메모 | **상태가 `승인`인 책만** 학생에게 공개됩니다. 초안은 `검토중`으로 둡니다. |
| `퀴즈문제` | 도서ID · 번호 · 문제 · 보기1~4 · 정답 | 정답은 1~4 숫자. 보기는 2~4개. 한 책에 10문제를 권장합니다. |
| `퀴즈응시` | 응시 시각 · 학년 · 반 · 이름 · 도서ID · 책 제목 · 점수 · 결과 | 앱이 자동으로 쌓습니다. 재도전을 허용하려면 해당 `실패` 줄을 지웁니다. |
| `출제요청` | 첫 요청 시각 · 책 제목 · 요청 수 · 최근 요청 · 상태 | 퀴즈 없는 책을 기록할 때마다 쌓입니다. 퀴즈를 만들면 상태를 `완료`로 바꿉니다. |

책 제목은 지은이 괄호, 띄어쓰기, 문장부호를 빼고 비교합니다. `어린 왕자`로 등록하면 학생이 `어린왕자(생텍쥐페리)`라고 써도 같은 책으로 인식합니다.

### 선생님 퀴즈 관리 화면 (`/teacher.html`)

학생 화면에는 링크가 없고, 주소를 직접 열어 비밀번호로 들어갑니다. 비밀번호는 코드에 없고 Apps Script 편집기의 **프로젝트 설정 > 스크립트 속성**에 `TEACHER_PASSWORD`로 저장합니다. 화면은 비밀번호를 메모리에만 두며, 20번 틀리면 15분 동안 잠깁니다.

- **퀴즈 목록**: 모든 퀴즈를 상태(검토중·승인·보류)와 함께 보여 줍니다.
- **편집**: 문제·보기·정답(동그라미)을 고치고 문제를 더하거나 지웁니다. `저장`은 상태를 그대로 두고, `저장하고 승인`을 누르면 바로 학생에게 공개됩니다. `보류`·`검토중으로`는 학생 화면에서 내립니다. 승인된 퀴즈를 고치면 학생 화면에 바로 반영됩니다.
- **출제 요청**: 요청 수가 많은 순서로 보여 주며, `퀴즈 만들기`는 제목·지은이를 채운 새 퀴즈를 열고 `완료`는 요청을 닫습니다.

시트를 직접 고쳐도 같은 결과입니다. 화면은 시트의 같은 칸을 읽고 씁니다.

### 새 퀴즈 만들기

1. 관리 화면의 `출제 요청`에서 요청이 많은 책을 고릅니다.
2. Claude에게 "『책 제목』(지은이), ○단계로 퀴즈 10문제 초안을 `검토중`으로 넣어 줘"라고 요청하거나, 관리 화면에서 직접 만듭니다.
3. 책을 읽은 선생님이 문제와 정답을 확인하고 고칩니다. **AI 초안은 책 내용을 틀리게 만들 수 있으니 반드시 검토합니다.**
4. `저장하고 승인`을 누르면 학생에게 공개됩니다. 출제 요청은 `완료`로 닫습니다.

### 검증

`tests/quiz-ui.test.js`는 가상 서버로 퀴즈 안내, 미응답 차단, 통과·실패·재도전 제한, 화면이 모르는 퀴즈 도서의 서버 차단, 퀴즈 없는 책의 출제 요청을 확인합니다. `tests/teacher-ui.test.js`는 관리 화면의 로그인, 목록, 편집·승인, 출제 요청 처리를 확인합니다. 서버 채점 규칙과 관리 기능은 Apps Script 프로젝트의 `tests/quiz.test.js`, `tests/teacher.test.js`가 실제 서버 코드를 메모리 시트로 실행해 확인합니다.
